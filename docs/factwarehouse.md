# 量价事实仓语义与运行说明

本文固定程序的业务语义裁决、表模型、守恒边界与操作流程。与 `docs/source-contract.md`
（来源资料约定）配套：来源约定说"资料是什么意思"，本文说"仓里怎么成形、怎么守恒、怎么查"。

## 1. 分层与处理流水线

```
data/ 原始资料
  -> ingest     指纹核验 + 类型解析 + 截止日标记（included_in_cutoff）
  -> validate   引用与业务规则核对（error 阻断成形 / warning 留痕）
  -> pricing    清单价格时间线（追溯改价回溯登记，纯范围变化不动价格）
  -> facts      五类最小事实行（实物/验收覆盖/计量状态/价值/现金 + 不可分解层）
  -> storage    SQLite 成形（raw_* 原始层 + *_f 事实层 + v_* 视图），只读连接
  -> conservation 从最小事实行独立重算 23 项守恒检查
  -> release    不可变移交期目录 + manifest 清单 + 平面导出
```

每一期 release 是独立目录：`state/releases/<id>/{warehouse.sqlite, manifest.json, exports/}`。
已存在的 release 拒绝改写；后续变更只能进新一期，再用 `diff` 说明更正影响。

## 2. 表模型与粒度

### 2.1 原始层（不可删改的留痕）

- `raw_bill_item_f` 清单版本行（按 `item_key` 解释版本，`line_no` 可跨版本重用）
- `raw_measure_f` 计量全部修订（含 `included_in_cutoff`）
- `raw_acceptance_link_f` 验收覆盖原始状态与 supersedes 链
- `raw_variation_f` 变更原始口径
- `raw_payment_f` 支付流水原始口径

### 2.2 事实层（每个事实只存一次，禁止预连接宽表）

| 表 | 粒度 | 说明 |
| --- | --- | --- |
| `physical_measure_f` | 每计量号一行 | 只取最新修订；`superseded_revisions` 留痕 |
| `acceptance_cover_f` | 每覆盖一行 | is_active / is_disputed / 认可量 / 争议量 |
| `measure_status_f` | 每计量一行 | 实物、有效覆盖、无争议、争议主张、超量、待认可 |
| `value_f` | 每覆盖或每待认可量一行 | 数量×适用单价；状态 recognized/disputed/pending/inactive_basis |
| `lump_value_f` | 每个无单价清单行 | 整栋总价不可分解层，禁止分摊到房间 |
| `bill_total_f` | 每清单版本一行 | 合同口径总额，与已形成价值分开列报 |
| `variation_lineage_f` | from×to 配对 | 拆项价值来源血缘；scope_only 标记纯范围变化 |
| `price_timeline_f` | 每价格段一行 | 左闭右开；来源 bill: 或 variation: |
| `payment_f` | 每流水一行 | 依据三分量 + 未解释差额 + 失去依据部分 |
| `payment_range_f` | 支付×验收单 | 声明范围（多对多） |
| `cash_basis_bridge_f` | 支付×价值行 | 依据桥接，含已分配额与容量外标记 |
| `build_warning_f` | 每条告警 | 超量争议、现金未解释等 |

视图 `v_measure_status / v_space_summary / v_item_summary / v_payment_cover`
全部从最小事实行聚合；跨域关系只走桥接表，因此多对多连接不会让金额重复出现。

## 3. 四条守恒边界

### 3.1 实物边界（physical）

- 同 `measure_id` 的修订是**替代**：实物量只计最高 `revision`，旧修订在原始层留痕。
- 修订只允许更正数量/日期，不得改清单版本或空间锚点（validate 拦截）。
- 守恒检查：物理事实合计 = 原始最新修订合计；每计量号仅一行最新事实。

### 3.2 验收边界（acceptance）

- 一张验收单可认可多张计量的一部分；一次计量可跨多张验收单（多对多，逐覆盖行存储）。
- `supersedes` 与 `status=rejected` 的覆盖为失效依据（inactive_basis），不新增实物认可。
- 有效认可合计超过最新实物量时，**全部竞争覆盖标记争议**，不按单据先后选赢家；
  超额量显式列为 `over_coverage_quantity`；未争议计量的事实独立保留、继续可查。
- 驳回后复验不增加原实物工程量：只看有效覆盖的认可量。

### 3.3 价值边界（value）

- 每行价值 = 数量（Decimal 字符串）× 适用单价（整数分），ROUND_HALF_UP 落整数分，
  全程 `decimal` 精确运算，不用二进制浮点。
- 适用单价按**事件自身日期**查价格时间线：
  - 追溯变更（retroactive=true 且带价）：新价对该清单项 `measured_on >= 生效日`
    的事件生效；更早事件保留旧价，绝不用当前单价重算全部历史；旧价格段保留可查。
  - 纯范围变化（retroactive=false，如整栋拆项）：不写任何价格段，只登记血缘；
    新清单项的初始价来自其自身清单行。项目总价不变不代表可以忽略拆项价值来源。
- 价值状态互不混淆：`recognized`（无争议认可）、`disputed`（争议主张，不确认）、
  `pending`（实物已形成但尚无有效覆盖）、`inactive_basis`（失效覆盖，仅供现金解释）。
- 无单价清单（整栋总价）进入 `lump_value_f`：**缺少分解依据就保留在不可分解层，
  不平均分摊给每个房间**，也不产生逐量价值行。
- 守恒检查：逐行价值重算一致；逐计量 认可+待认可=实物重算价值，争议计量不计认可。

### 3.4 现金边界（cash）

- 支付是现金事实，与认可工程价值是两件事；净现金独立列报，绝不充作完成量。
- 每笔支付按声明的验收范围解析依据，按 认可→争议→失效 的顺序、以付款绝对额为上限
  逐行分配；分配不进去的依据行保留在桥接表并标 `outside_payment_capacity` /
  `partially_allocated`，不删除、不裁剪。
- 恒等式：`认可依据 + 争议依据 + 失效依据 + 未解释差额 = 付款绝对额`，
  未解释差额恒非负；禁止平均分摊，禁止负差额轧账。
- `basis_impaired_fen` 显式指出支付中有多少已失去（或尚未取得）认可依据；
  系统**不自动生成退款**。
- 负数流水必须带 `reverses` 与明确验收范围，禁止无主退款与连环冲销（validate 拦截）。
- 守恒检查：桥接已分配合计 = 支付依据分量合计（多对多不重复计数）；
  退款均有原支付引用。

## 4. 分期移交与期间差异

- `build --release ID [--cutoff YYYY-MM-DD]`：带日期事实按截止日过滤，
  被排除行保留在原始层且 `included_in_cutoff=0`；验收覆盖无日期字段，不参与截止过滤。
- `manifest.json` 固化：四边界总量、告警、校验发现、守恒结论、
  以及 `pending_evidence_gap`（待认可价值 / 现金未解释 / 失去依据金额）——
  尚待补证的量价差额只挂账可查，不确认收入、不自动退款。
- `diff --from A --to B`：实物更正、验收覆盖重审、价格段变化、价值分量差额、
  现金依据变化分组输出；旧期数值不被改写。计量更正到来时，认可量、适用价格、
  验收覆盖关系在新一期被同时重审。

## 5. 钻取链路

- 认可金额追来源：`value --acceptance-id` / `--value-id`
  → 价值行（单价、价格来源、价格时间线）→ 验收覆盖（含替代/争议标记）
  → 计量修订与空间 → 清单版本与变更血缘。
- 支付追解释：`payment --payment-id`
  → 声明验收范围 → 桥接到各状态价值依据（已分配/容量外）
  → 未解释差额与 basis_impaired → reverses / reversed_by 冲销链。
- 空间汇总 `spaces` 明确列出被排除的不可分解整栋款；
  清单汇总 `items` 把合同总额与已形成认可价值并排而非合并。
